## Acceptance criteria

1. Re-read linked account history coverage before income/cash-flow conclusions and qualify any freshness limitation.
2. Compute a full-history household income baseline from broad posted inflow candidates across every relevant connected depository/income-receiving account, with transfers included in retrieval and excluded/reconciled only after classification. Do not count account-to-account transfers, refunds, card credits or ambiguous rows as earned household income.
3. Preserve separate useful income views: full-history household average, recent productive-work pace and other explicit source-budget income projections. No one view silently overwrites another.
4. Reconcile linked current cash, liabilities, investment/retirement balances and material recurring obligations against the private command-center model; explicit mismatches become annotated assumptions/conflicts rather than silent overwrites.
5. Record the customer's spouse-retirement instruction as a private `USER_CONFIRMED_MIRROR_ASSUMPTION`: spouse 401(k) planning balance equals the linked primary-user 401(k) balance until direct spouse-provider evidence becomes available. Never label the mirrored value provider-observed and never mutate the linked primary balance.
6. Retire the older household/Pig Phet budget source from active forecast/comparison use because the newer shared Budget and Income source supersedes it. Do not delete the old source file/entity/history; mark it retired/superseded and remove it from active projection formulas/views.
7. Model exactly one remaining Pig Phet WGU term. Use the customer-confirmed six-month horizon from September 1, 2026 as a planning due date of March 1, 2027 unless stronger source evidence proves another date. Keep the actual term amount explicitly unverified if not provider-confirmed. Preserve the newer source savings-rate evidence and show funded/remaining pace against the term target.
8. Allowance state consists of exactly two household balances, Matthew and Pig Phet, each with the established recurring first-of-month accrual. Only spend assigned to that person may debit that person's allowance. Household/unassigned allowance spend fails closed until person attribution is resolved. Reclassification/replay remains idempotent.
9. Define live net worth as a transparent projection over current linked assets minus linked liabilities plus clearly labelled user-confirmed non-provider planning assets only when the view explicitly includes assumptions. Dashboard must distinguish provider-only net worth from assumption-adjusted household planning net worth.
10. Establish monthly budget freeze semantics: each month has an immutable opening/frozen budget baseline; actuals accumulate separately; month-close variance is preserved; surplus rolls forward only through an explicit carry adjustment and deficit creates an explicit next-month trim adjustment. Prior month budgets are never rewritten after close.
11. Each monthly carry/trim adjustment records amount, source month and a short reason/annotation so next month's budget explains why it differs from its baseline.
12. Surface the core current-month control state on the main dashboard: current/frozen budget, actual-to-date, remaining or overage, projected month-end variance, prior-month carry/trim, provider-only net worth, assumption-adjusted planning net worth, both allowance balances, WGU funding state and Financial Escape window/confidence.
13. Exact post-write readback verifies no duplicate canonical IDs, no broken relation endpoints, allowance debit integrity, budget-control formulas, and no spreadsheet error values in touched ranges.
14. Private values remain in the private workbook; public Git contains only sanitized rules/evidence.
