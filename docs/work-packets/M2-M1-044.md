## Objective

Implement one strict portable Studio worker-task contract plus one worker-local binding resolver. The portable task carries only review-ready customer/controller execution semantics and logical binding IDs. Private worker configuration resolves those logical IDs to the existing executable `WorkerManifest` fields locally.

This packet does not implement the network transport itself.

## Portable task contract

The portable task must contain only:

- review-ready Studio draft identity and normalized objective;
- logical source binding ID;
- exact base Git SHA;
- controller-owned candidate branch name;
- canonical sorted editable-path allowlist;
- fixed test argv;
- logical model-profile ID;
- bounded repair/test/model/wall-clock budgets.

It must not contain physical source path, hostname, IP, MAC, machine serial, credential, token, VPN material, concrete model endpoint, concrete model name/path, private provider resource ID or private deployment topology.

Canonical serialization and SHA-256 task identity cover every portable execution field.

## Worker-local binding contract

Worker-local private binding material maps:

- one logical source binding ID → one local repository path;
- one logical model-profile ID → one loopback OpenAI-compatible endpoint + concrete local model identifier.

Binding material is an in-memory/runtime configuration contract only. This packet does not persist it into MIRROR, Git, portable task JSON, durable compute-job payloads or public receipts.

The binder must require exactly one matching source binding and one matching model binding, then construct the existing `WorkerManifest`. Existing manifest validation remains authoritative for repository/path/branch/test/budget/model endpoint shape, including loopback-only model access.

## Security and privacy invariants

- Logical task IDs are not physical host bindings.
- Portable serialization never includes private binding values.
- Missing, duplicate or mismatched bindings fail closed.
- Binding cannot rewrite draft/objective, base SHA, branch, allowlist, tests or budgets.
- Private binding can supply only local repo path, loopback model endpoint and concrete model identifier.
- No raw shell/Python/inference service is exposed.
- No network listener or worker-supplied trust claim is introduced.
- Public tests use synthetic logical IDs and temporary/synthetic paths only.

## Acceptance criteria

1. Review-ready Studio intent projects to one validated portable task without physical binding material.
2. Portable task serialization is deterministic and canonical.
3. Task SHA-256 changes when any execution-relevant portable field changes.
4. Task validation rejects malformed draft/logical IDs, base SHA, branch, allowlist, test argv or budgets.
5. A worker-local binding set resolves the task to the exact existing valid `WorkerManifest`.
6. Missing/duplicate/mismatched logical source/model bindings fail closed.
7. Non-loopback model endpoint is rejected through the existing manifest boundary.
8. Customer objective semantics and controller-owned base/branch/path/test/budget policy survive binding unchanged.
9. Portable task/receipt material excludes physical repo path, concrete model endpoint/name and other private deployment details.
10. Code ownership and direct tests are registered; full repository CI remains green.
11. Exact-head CI and post-merge exact-SHA CI/readback are mandatory before integration verification.
12. No live private worker, network transport, real host isolation, LM Studio or hardware execution claim is made from synthetic CI.
