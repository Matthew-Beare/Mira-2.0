## Objective

Perform the first bounded protected-production migration into the private MIRA 2.0 MIRROR fabric by preserving the three existing household vehicle asset identities and minimum ownership/provenance relations, while auditing the last three actual vehicle-registration payments so registration planning can be linked to the correct vehicles only where evidence supports it.

This packet does not migrate the full legacy receipt/asset database, does not redesign the entire finance workbook, and does not create new vehicle UUIDs. It exists to prove safe identity continuity across the protected legacy asset source and the current MIRA 2.0 finance/MIRROR projection.

## Migration scope

Authorized writes are limited to:

1. three pre-existing household vehicle ASSET identities, preserving legacy immutable UUIDs;
2. minimum ownership/source-provenance relations required to establish those identities in the current MIRA 2.0 Entity Registry/Relations model;
3. registration-plan relations only when historical transaction/email/receipt evidence supports the specific vehicle mapping;
4. migration-control/readback diagnostics needed to prove parity, idempotency and rollback boundaries.

No tire, wheel, receipt-line, fitment, warranty, technical-specification, location, inventory or broad legacy asset migration is authorized here unless a hard dependency blocks the three-vehicle proof.

## Acceptance criteria

1. Confirm source and target pre-migration backups remain readable and source/target originals are distinct resources.
2. Perform zero-write collision/dry-run mapping for all three legacy vehicle UUIDs against the target Entity Registry and Relations tables.
3. Audit the connected financial transaction history for the most recent three actual government/registration payments, without assuming every County Clerk charge belongs to a different car.
4. Audit registration-related Gmail/receipt/Drive evidence around those transactions to determine whether each payment can be mapped to the Honda, WRX or Miata. Unknown mapping remains unknown.
5. Migrate the three legacy vehicle UUIDs exactly; no replacement UUIDs or duplicate physical vehicle entities.
6. Preserve minimum ownership/provenance semantics and keep private identifiers out of public Git.
7. Registration plan items remain exactly three total; each may be linked to a vehicle only when supported by evidence.
8. Migration is idempotent: replay/upsert produces no duplicate Entity or Relation IDs and no second vehicle identity.
9. Provider-observed financial transactions remain unchanged; migration writes only MIRROR identity/relation/planning state.
10. Post-write readback proves target contains exactly the migrated vehicle identities, zero duplicate Entity IDs, zero duplicate Relation IDs, and zero broken relation endpoints attributable to this migration.
11. Rollback identifiers are recorded privately so only migration-created target rows can be removed/restored without touching protected source data.
12. Public Git records only sanitized acceptance evidence and does not contain vehicle UUIDs, transaction IDs, account IDs, emails, VINs, plates or receipt contents.
