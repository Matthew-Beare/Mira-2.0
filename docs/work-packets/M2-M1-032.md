## Review corrections before release

The first staged implementation accepted only the nested `IntegrationPlan`. That object carried exact candidate base/head/source evidence but did not carry the enclosing packet/work identity. During pre-merge review this was treated as a real provenance weakness rather than waved through: the API was changed to require the full `StudioCompetitionDecision`, and staging now validates packet ID, work ID, competition base, selected candidate evaluation and nested integration-plan provenance before accepting the staged contract.

A second review found that the competition decision did not yet carry the originating feature scope. Without that binding, a correctly reviewed source proposal could theoretically be relabelled downstream onto a different set of feature IDs. The decision now preserves exact `feature_ids` from `StudioWorkSpec`, and staging requires the contract feature set to match exactly. Regression coverage proves feature relabelling fails closed.

The release-authority implementation is the exact CI-tested head `ebc2bbdddc0b63b54fa51be2803518a2c42276f0`.
