## Admission contract

`RuntimeIsolationEvidence` is trusted controller input representing an observation from the actual host/runtime boundary. It binds:

- worker ID;
- principal ID;
- runtime ID;
- observation time;
- explicit attestation kind;
- restricted process identity;
- filesystem isolation;
- process-tree containment;
- credential isolation;
- enforced resource limits;
- explicit network mode;
- provenance SHA-256.

The public admission code does not decide how those properties are implemented. A later private/live adapter may use a restricted OS account, container/service sandbox, hypervisor boundary or another mechanism, but it must produce trustworthy evidence from the host boundary rather than accepting worker-supplied booleans as truth.

## Required durable truth

Admission requires all of the following:

1. `ComputeJobView` is `leased` or `running` with an unexpired lease.
2. Lease worker ID matches the exact durable worker record.
3. Job operation/service match controller-owned restricted-runtime policy.
4. Cancel-requested work cannot enter execution.
5. Optional policy binds the durable input artifact to the exact Studio draft ID.
6. Worker identity is `verified`, approval is `approved`, local compute is not `off`, availability is `ready` or `busy`, health is `healthy`, and interactive lock is false.
7. Job data classification is explicitly allowed by the worker.
8. Worker capabilities satisfy both durable job requirements and restricted-runtime policy requirements.
9. Isolation evidence worker/principal/runtime identity exactly matches the worker registry record.
10. Attestation kind is allowlisted by controller policy.
11. Isolation evidence is not future-dated or stale.
12. All required host-isolation properties are true and network mode exactly matches policy.

## Permit semantics

A successful admission issues `StudioExecutionPermit` containing only logical IDs, policy/lease binding, manifest digest, isolation provenance digest, attestation kind and UTC issue/expiry timestamps.

The permit contains no repository path, model endpoint, model name, test argv, credential, hostname, IP, MAC, hardware serial or raw customer/source contents.

Permit expiry is the earlier of the controller policy TTL and the durable compute lease expiry. Execution revalidates current job/worker/isolation state and the exact manifest before calling the lower local worker.

## Studio bridge integration

`run_review_ready_intake_restricted()` is the controller-facing safe path:

1. validate/build a `WorkerManifest` from review-ready ordinary-language intake plus controller-owned execution policy;
2. issue a restricted-runtime permit from durable job/worker truth plus trusted host-isolation evidence;
3. revalidate that permit immediately before local execution;
4. enter `run_manifest()` only after those gates succeed;
5. return both admission permit and existing worker evidence.

The lower worker remains a bounded execution primitive and testable CLI. This packet does not pretend Python-level admission itself creates OS containment; it makes trustworthy containment evidence a prerequisite for the safe controller path.

## Acceptance criteria

2. Short-lived permit binds policy/job/lease/worker/principal/runtime/draft/manifest/isolation provenance.
3. Lease mismatch, cancellation and expiry fail closed.
4. Worker identity/approval/local-compute/health/availability/interactive-lock failures fail closed.
5. Data-classification and capability mismatch fail closed.
6. Isolation worker/principal/runtime mismatch fails closed.
7. Disallowed, stale, future or incomplete isolation evidence fails closed.
8. Network isolation must exactly match controller policy.
9. Changing any manifest execution field invalidates the permit before lower-worker entry.
10. Permit expiry blocks execution before lower-worker entry.
11. Controller-facing Studio bridge issues/revalidates permit before entering the executable worker.
12. Permit exposes no private endpoint/path/credential material.
13. Existing repository CI remains green.
14. Exact-head and post-merge CI/readback are required before closure.
15. No live host containment, private LM Studio instance, physical worker or production deployment claim is made from synthetic CI alone.
