## Admission contract

`RuntimeIsolationEvidence` is trusted controller input representing an observation from the actual host/runtime boundary. It binds:

- worker ID;
- principal ID;
- runtime ID;
- observation time;
- explicit attestation kind;
- restricted process identity;
- filesystem isolation;
- process-tree containment;
- credential isolation;
- enforced resource limits;
- explicit network mode;
- provenance SHA-256.

The public admission code does not decide how those properties are implemented. A later private/live adapter may use a restricted OS account, container/service sandbox, hypervisor boundary or another mechanism, but it must produce trustworthy evidence from the host boundary rather than accepting worker-supplied booleans as truth.

## Required durable truth

Admission requires all of the following:

1. `ComputeJobView` is `leased` or `running` with an unexpired lease.
2. Lease worker ID matches the exact durable worker record.
3. Job operation/service match controller-owned restricted-runtime policy.
4. Cancel-requested work cannot enter execution.
5. Optional policy binds the durable input artifact to the exact Studio draft ID.
6. Worker identity is `verified`, approval is `approved`, local compute is not `off`, availability is `ready` or `busy`, health is `healthy`, and interactive lock is false.
7. Worker identity verification/heartbeat ordering is valid and heartbeat freshness satisfies explicit controller policy.
8. Job data classification is explicitly allowed by the worker.
9. Worker capabilities satisfy both durable job requirements and restricted-runtime policy requirements.
10. Isolation evidence worker/principal/runtime identity exactly matches the worker registry record.
11. Attestation kind is allowlisted by controller policy.
12. Isolation evidence is not future-dated or stale.
13. All required host-isolation properties are true and network mode exactly matches policy.

## Permit semantics

A successful admission issues `StudioExecutionPermit` containing only logical IDs, complete runtime-policy digest, lease binding, manifest digest, isolation provenance digest, attestation kind and UTC issue/expiry timestamps.

The permit contains no repository path, model endpoint, model name, test argv, credential, hostname, IP, MAC, hardware serial or raw customer/source contents.

Permit expiry is the earlier of the controller policy TTL and the durable compute lease expiry. Execution revalidates current job/worker/isolation state and the exact manifest/policy before calling the lower local worker. Legitimate newer worker heartbeat/isolation observations remain acceptable if all original permit bindings still hold.

## Studio bridge integration

`run_review_ready_intake_restricted()` is the controller-facing safe path:

1. validate/build a `WorkerManifest` from review-ready ordinary-language intake plus controller-owned execution policy;
2. issue a restricted-runtime permit from durable job/worker truth plus trusted host-isolation evidence;
3. revalidate that permit immediately before local execution;
4. enter `run_manifest()` only after those gates succeed;
5. return both admission permit and existing worker evidence.

The lower worker remains a bounded execution primitive and testable CLI. This packet does not pretend Python-level admission itself creates OS containment; it makes trustworthy containment evidence a prerequisite for the safe controller path.

## Semantic/adversarial review findings

Three defects were found and repaired before closeout:

1. **Stale worker-state authority:** initial admission checked health/locks but did not bound heartbeat freshness. The gate now rejects stale/future heartbeat evidence and invalid identity-verification/heartbeat ordering.
2. **Revalidation/newer-heartbeat flaw:** initial permit revalidation reconstructed a permit using current worker evidence at the original issue timestamp, so a legitimate newer heartbeat could be rejected as future-dated. Revalidation now validates current context independently and checks the original permit fields/integrity directly.
3. **Incomplete policy binding:** initial permit material carried only a policy ID. The permit now includes `policy_sha256`, binding all controller-owned capability, attestation, freshness, TTL, network and draft-binding policy fields.

The controller-facing bridge also gained a direct composition test proving permit issuance occurs before authorized lower-worker entry.

No further blocking defect was identified during bounded review. The durable compute job already retains its input SHA-256; this packet binds the exact content-derived Studio draft ID plus complete manifest/policy and does not invent a second artifact-store contract.
