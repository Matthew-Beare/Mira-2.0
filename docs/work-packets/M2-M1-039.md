# M2-M1-039 — Financial Escape twice-daily refresh reliability repair

## Objective

Restore trustworthy Financial Escape refresh/readback for the 02:45 and 14:45 America/New_York brief cycle before ordinary MIRA Studio work resumes.

## Trigger

On 2026-09-11 the customer explicitly challenged whether the Financial Escape plan was actually updating every day and requested a visible last-update indicator in the dashboard. Live audit showed the scheduler was firing while the workbook remained stale at 2026-09-07.

## Failure evidence

- AM and PM MIRA brief automations are enabled for 02:45 and 14:45 America/New_York.
- The AM scheduler had invoked on 2026-09-11.
- `Today & Accounts` remained as-of 2026-09-07.
- `Daily Snapshots` contained no row later than 2026-09-07.
- `FIN-LIVE-VERIFY-001 COMPLETE` was dated 2026-09-07.
- Current linked-account values materially differed from stale workbook values.

A scheduler run therefore cannot be treated as proof of a successful Financial Escape refresh.

## Repair contract

1. Authoritative account/provider evidence is refreshed first.
2. Source freshness=unknown remains explicitly unknown.
3. Provider transactions/balances are money authority; receipts/orders/email are classification evidence and never duplicate money events.
4. AM inserts or updates exactly one current-date snapshot; PM may update that same date but never add a duplicate.
5. Dashboard freshness is fail-closed: both live-view date and latest snapshot date must equal today for `CURRENT`.
6. Stale state must be visible on the dashboard and in a brief; stale finance status cannot be presented as current.
7. Successful run evidence requires post-write readback, not scheduler invocation.
8. Historical data is not silently rewritten. Corrections require explicit provenance.
9. Verified-net-worth treatment must match its declared formula, including linked retirement assets when the formula says they are included.
