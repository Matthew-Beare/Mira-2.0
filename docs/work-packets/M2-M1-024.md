## Objective

Implement the next dependency-ranked compute-fabric slice after the merged worker routing/identity/registry packets: a provider-neutral durable compute-job control plane over STORE-001-compatible structured state.

The control plane must preserve stable job identity, secret-free task requirements, deterministic priority ordering, bounded attempts, worker leases, retry/idempotency semantics, cancellation, pause/preempt/resume checkpoints, lease-expiry recovery and exact result provenance. It must not execute code, expose raw shell/Python/inference endpoints, choose private machines, authenticate workers, wake/shut down hardware, or claim live local-model execution.

## Acceptance criteria

1. Compute jobs persist through `StructuredStateAdapter` using a dedicated `compute_job` resource type and strict schema.
2. Job submission is replay-safe and stores only secret-free operation requirements plus artifact IDs/hashes, never raw task payloads or private host/path/credential fields.
3. Eligible queued jobs are leased deterministically by priority, creation time and job ID.
4. A lease is bound to one worker ID and lease ID, has an explicit UTC expiry and increments bounded attempt count exactly once.
5. Only the matching active lease may start, checkpoint/pause, acknowledge cancellation, fail or complete a job.
6. Queue cancellation is immediate for queued/paused jobs; active jobs become cancellation-requested until the owning worker acknowledges or lease recovery resolves them.
7. Pause/preempt records a checkpoint artifact ID + SHA-256 and returns the job to an explicit paused state; resume requeues without discarding the checkpoint.
8. Retryable failures and expired leases requeue only while attempts remain; otherwise they fail terminally with bounded error state.
9. Completion records exact result artifact ID + SHA-256, worker ID, runtime ID, completion time and attempt number.
10. Exact retries of successful state transitions are replay-safe; changed-material reuse fails closed through state validation/STORE-001 idempotency semantics.
11. Deterministic synthetic tests cover lifecycle, lease ownership, retry, cancellation, preemption/resume, expiry recovery, result provenance, secret-free schema and compatibility with the existing command sequencer tests.
12. Exact-head CI must pass before merge. No live worker/network/model/power/private deployment evidence is claimed.
