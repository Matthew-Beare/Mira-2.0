## Objective

Implement the next dependency-ranked compute-fabric slice after the merged worker routing/identity/registry packets: a provider-neutral durable compute-job control plane over STORE-001-compatible structured state.

The control plane must preserve stable job identity, secret-free task requirements, deterministic priority ordering, bounded attempts, worker leases, retry/idempotency semantics, cancellation, pause/preempt/resume checkpoints, lease-expiry recovery and exact result provenance. It must not execute code, expose raw shell/Python/inference endpoints, choose private machines, authenticate workers, wake/shut down hardware, or claim live local-model execution.

## Acceptance criteria and evidence

1. **Durable STORE-001 jobs:** implemented with a dedicated strict `compute_job` resource schema through `StructuredStateAdapter`.
2. **Secret-free submission:** implemented; job state stores operation/capability metadata and artifact IDs/SHA-256 values, never raw task payloads, credentials, host bindings, model paths, shell commands, Python code or inference endpoints.
3. **Deterministic leasing:** implemented by priority, creation time and job ID with required capability filtering.
4. **Lease identity/attempt bounds:** implemented; active lease IDs are globally collision-checked and exact lease replay does not increment attempts twice.
5. **Lease ownership:** implemented for start, pause, cancellation acknowledgement, failure and completion.
6. **Cancellation:** implemented for queued/paused immediate terminal cancellation and active cancellation request + owning-worker acknowledgement.
7. **Pause/preempt/resume:** implemented with checkpoint artifact ID + SHA-256 retained across explicit requeue/resume.
8. **Retry and expiry recovery:** implemented with bounded attempts, retryable failure requeue and terminal exhaustion; expired leases deterministically requeue/fail/cancel.
9. **Result provenance:** implemented with exact result artifact ID/SHA-256, worker ID, runtime ID, attempt number and UTC completion time.
10. **Replay safety:** hardened after adversarial review. Each durable job records only SHA-256 receipt hashes for the last idempotency identity and canonical transition material. Exact same-key/same-material retries replay without revision churn; same-key changed-material reuse fails closed. Raw idempotency keys are not persisted.
11. **Adversarial synthetic tests:** cover lifecycle, deterministic selection, lease collision/ownership, capability-bound lease replay, cancellation and acknowledgement timestamp binding, pause timestamp binding, fail-after-requeue exact retry, bounded attempts, expiry, result provenance, strict schema/private-field rejection and secret-free state shape.
12. **Repository verification:** CI #526 passed end-to-end on hardened implementation head `8916fd5476ffc85c8f97e6ef9c50ac21b4024964`, including compile, feature registry, lifecycle ledger, starter distribution, work-session alignment, code ownership, Android unit/proof/provenance gates, Python unit tests and Workspace Apps Script tests. One final exact-head CI is required after this documentation-only closeout before merge.
