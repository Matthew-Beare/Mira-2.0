## Implementation-discovered prerequisite: exact-job lease

`ComputeJobControlPlane.lease_next()` is intentionally worker-pull and selects the highest-ranked eligible queued job globally. Studio dispatch is controller-routed: the router first selects an exact worker for one exact Studio job. Calling `lease_next()` after that routing step could legally lease a different queued job with an earlier queue sort key.

Therefore this packet adds a replay-safe **exact-job lease primitive** to the existing `ComputeJobControlPlane`. It preserves all existing lease invariants and does not become a second scheduler.

The exact-job lease operation:

1. targets one explicit queued `job_id`;
2. requires exact worker ID, worker capabilities, lease ID and UTC lease interval;
3. rejects cancelled, non-queued or attempt-exhausted jobs;
4. rejects workers missing any job-required capability;
5. rejects an active lease-ID collision with another job;
6. increments attempts exactly once;
7. preserves idempotent same-key/same-material replay without attempt/revision churn;
8. fails closed on same-key changed material;
9. leaves `lease_next()` behavior unchanged for worker-pull scheduling.

## Dispatch contract

The controller-facing dispatch path:

1. accepts a review-ready `StudioIntakeDraft` plus controller-owned execution/dispatch/restricted-runtime policy;
2. deterministically derives the complete `WorkerManifest` through the existing Studio execution bridge;
3. submits or exact-replays one durable compute job bound to the draft ID and manifest digest;
4. reads durable workers from `WorkerRegistryService` rather than accepting arbitrary worker objects as routing authority;
5. projects each worker through the existing worker advertisement/freshness contract using externally supplied provider capability evidence;
6. routes through existing `route_runtime()` policy/capability logic;
7. resolves the selected lane/runtime back to exactly one durable worker, failing closed on missing or ambiguous mapping;
8. leases the exact submitted Studio job to that exact worker using the new exact-job lease primitive;
9. starts that exact lease in the existing compute control plane;
10. requires trusted `RuntimeIsolationEvidence` for the selected worker/runtime and enters the M2-M1-042 restricted execution path;
11. on successful lower-worker evidence, persists a secret-free result artifact identity/digest and completes the exact durable job with selected worker/runtime provenance;
12. on bounded execution failure, persists deterministic failure state through the existing control plane without fabricating success;
13. never merges, pushes, activates, publishes or installs the resulting Studio candidate.
