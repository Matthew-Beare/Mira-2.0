## Implementation-discovered prerequisite: exact-job lease

`ComputeJobControlPlane.lease_next()` is intentionally worker-pull and selects the highest-ranked eligible queued job globally. Studio dispatch is controller-routed: the router first selects an exact worker for one exact Studio job. Calling `lease_next()` after that routing step could legally lease a different queued job with an earlier queue sort key.

Therefore this packet must add a replay-safe **exact-job lease primitive** to the existing `ComputeJobControlPlane`. It must preserve all existing lease invariants and must not become a second scheduler.

The exact-job lease operation must:

1. target one explicit queued `job_id`;
2. require exact worker ID, worker capabilities, lease ID and UTC lease interval;
3. reject cancelled, non-queued or attempt-exhausted jobs;
4. reject workers missing any job-required capability;
5. reject an active lease-ID collision with another job;
6. increment attempts exactly once;
7. preserve idempotent same-key/same-material replay without attempt/revision churn;
8. fail closed on same-key changed material;
9. leave `lease_next()` behavior unchanged for worker-pull scheduling.

## Dispatch contract

The controller-facing dispatch path must:

1. accept a review-ready `StudioIntakeDraft` plus controller-owned execution/dispatch/restricted-runtime policy;
2. deterministically derive the complete `WorkerManifest` through the existing Studio execution bridge;
3. submit or exact-replay one durable compute job bound to the draft ID and manifest digest;
4. read durable workers from `WorkerRegistryService` rather than accepting arbitrary worker objects as routing authority;
5. project each worker through the existing worker advertisement/freshness contract using externally supplied provider capability evidence;
6. route through existing `route_runtime()` policy/capability logic;
7. resolve the selected lane/runtime back to exactly one durable worker, failing closed on missing or ambiguous mapping;
8. lease the exact submitted Studio job to that exact worker using the new exact-job lease primitive;
9. start that exact lease in the existing compute control plane;
10. require trusted `RuntimeIsolationEvidence` for the selected worker/runtime and enter the M2-M1-042 restricted execution path;
11. on successful lower-worker evidence, persist a secret-free result artifact identity/digest and complete the exact durable job with selected worker/runtime provenance;
12. on bounded execution failure, persist deterministic failure state through the existing control plane without fabricating success;
13. never merge, push, activate, publish or install the resulting Studio candidate.
