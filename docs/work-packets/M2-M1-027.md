## Objective

Implement a provider-neutral read-only observability projection for the compute fabric using existing validated worker and compute-job views as source truth. Produce deterministic Prometheus-compatible metrics plus a Grafana-compatible PromQL panel plan without creating a second state authority or leaking private/high-cardinality identifiers.

This packet does not deploy Prometheus, Grafana, exporters on private machines, a scrape endpoint, alert delivery, hardware sensor collectors, cooling/power thresholds, or live private infrastructure.

## Source contracts

- `mira.service_state.WorkerRegistryView` is the worker-state source.
- `mira.command_sequencer.ComputeJobView` is the job-state source.
- Observability may aggregate and render those views but must never mutate or persist replacement worker/job truth.

## Bounded metric surface

The initial snapshot should expose aggregate gauges for:

- worker counts by bounded runtime/availability/health/identity/mode/interactive-lock state;
- worker heartbeat age maximum and stale-worker count by runtime kind;
- job counts and summed attempts by lifecycle state;
- maximum queued-job age;
- terminal job lifecycle duration count/sum/max by terminal state;
- terminal result counts by state and local/hosted/unknown runtime kind.

The renderer must use deterministic ordering and valid Prometheus text escaping. These are snapshot gauges rather than pretending mutable aggregate observations are monotonic counters.

## Privacy/cardinality rules

Metric labels and dashboard query variables in this packet must never include:

- worker ID;
- job ID;
- principal ID;
- lane ID;
- runtime ID;
- artifact IDs or hashes;
- hostname/IP/MAC/serial;
- model path/model secret;
- credential/token material;
- raw operation/input/error text.

Only bounded aggregate state dimensions are allowed. Runtime kind may be `local`, `hosted`, or derived `unknown` for terminal result reconciliation. No metric can make private host identity observable merely because a worker exists.

## Time semantics

- All input timestamps and `now` are explicit UTC ISO-8601 values.
- Future worker heartbeats, future job creation/start/finish times, negative durations and malformed timestamps fail closed.
- Worker staleness is a deterministic configured freshness window; it is observability evidence only and does not independently mutate worker health/availability.
- Queue age is measured only for queued jobs from `created_at` to `now`.
- Terminal lifecycle duration is wall-clock `created_at` to `finished_at`, not fabricated active CPU/GPU duration.
- This packet does not infer paused/running active compute duration from incomplete lifecycle history.

## Grafana-compatible query plan

Provide stable read-only PromQL expressions for at least:

1. total/ready/faulted workers;
2. stale worker count;
3. jobs by state;
4. oldest queued-job age;
5. failed jobs;
6. terminal jobs by runtime kind.

The query plan is configuration/projection only. It is not a deployed dashboard and never becomes state authority.
