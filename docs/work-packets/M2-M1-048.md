## Objective

Implement one strict portable Studio worker-task contract plus one worker-local binding resolver. The portable task carries only review-ready customer/controller execution semantics and logical binding IDs. Private worker configuration resolves those logical IDs to the existing executable `WorkerManifest` fields locally.

This packet does not implement network transport itself.

## Portable task contract

The portable task contains only:

- review-ready Studio draft identity and normalized objective;
- logical source binding ID;
- exact base Git SHA;
- controller-owned candidate branch name;
- canonical sorted editable-path allowlist;
- fixed test argv;
- logical model-profile ID;
- bounded repair/test/model/wall-clock budgets.

It must not contain physical source path, hostname, IP, MAC, serial, credential, token, VPN material, concrete model endpoint, concrete model name/path, private provider resource ID or private deployment topology. Canonical serialization and SHA-256 identity cover every portable execution field.

## Worker-local binding contract

Worker-local private binding material maps:

- one logical source binding ID -> one local repository path;
- one logical model-profile ID -> one loopback OpenAI-compatible endpoint plus concrete local model identifier.

Binding material stays worker-local runtime configuration. It is not serialized into the portable task, durable public job material, Git or provider-facing receipts. The binder requires exactly one matching source and model binding and constructs the existing validated `WorkerManifest`.

## Acceptance criteria

1. Review-ready Studio intent projects to one validated portable task without physical binding material.
2. Portable task serialization is deterministic and canonical.
3. Task SHA-256 changes when any execution-relevant portable field changes.
4. Validation rejects malformed draft/logical IDs, base SHA, branch, allowlist, test argv or budgets.
5. Worker-local bindings resolve the task to the exact existing valid `WorkerManifest`.
6. Missing/duplicate/mismatched logical source/model bindings fail closed.
7. Non-loopback model endpoints fail through the existing manifest boundary.
8. Customer objective and controller base/branch/path/test/budget policy survive binding unchanged.
9. Portable material excludes physical repo path, concrete model endpoint/name and other private deployment details.
10. Existing repository tests and ownership/alignment gates remain green on the current `main` lineage.
11. Exact-head CI plus expected-head merge and post-merge readback are mandatory before integration verification.
12. No live private worker, transport, host isolation, LM Studio or hardware claim is made from synthetic CI.
