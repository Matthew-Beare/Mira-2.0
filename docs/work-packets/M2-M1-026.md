## Objective

Create the deterministic trust seam that a later private self-hosted runner must consume before executing repository source. Arbitrary public fork/PR code must never become private-runner eligible merely because GitHub delivered an event or CI passed somewhere.

The packet separates two facts:

1. **Source trust** — whether the exact source commit is a successful canonical-repository `push` to the canonical branch from the canonical repository.
2. **Runner isolation** — whether the prospective runner is independently restricted enough for source execution.

A source-trusted commit without runner-isolation evidence stops at `requires_isolation`. Pull-request/fork source is `hosted_only` regardless of any runner-isolation claim.

## Bounded implementation

1. Add `project/ci_trust.py` with provider-specific GitHub event normalization but provider-neutral trust outcomes.
2. Preserve exact canonical repository, branch, source SHA, policy SHA, workflow/run identity and machine-readable reason codes in deterministic receipts.
3. Add a separate runner-isolation contract with restricted identity, ephemeral workspace, sandboxed source execution, no injected credentials and no private-LAN access as the minimum synthetic eligibility profile.
4. Only trusted canonical-main source plus safe isolation may evaluate to `private_runner_eligible`.
5. Add `.github/workflows/trusted-runner-gate.yml` triggered by completion of the existing `CI` workflow. The gate itself runs on GitHub-hosted infrastructure only, uses `contents: read`, checks out policy from the default branch rather than the triggering candidate SHA, and emits a preflight receipt artifact.
6. The GitHub-hosted gate intentionally supplies no runner-isolation evidence, so its successful trusted-main receipt remains `requires_isolation`; it is evidence for a later private scheduler, not authorization by itself.
7. Keep existing GitHub-hosted CI as the first-line execution environment for PR/fork code.

## Security/integrity rules

- No `pull_request_target` execution of candidate source.
- No `self-hosted` runner target is introduced by this packet.
- No repository secret is required by the preflight workflow.
- No private hostname, IP, runner label, hardware identity, LAN/VPN detail, credential or provider resource ID enters public source.
- A green PR is not equivalent to trusted private-runner source.
- A same-repository PR is still PR source and remains hosted-only.
- A successful push to a noncanonical branch remains hosted-only.
- Wrong repository/origin, failed CI, malformed SHA/provenance or unsupported event state fails closed.
- Runner isolation cannot upgrade untrusted source.
- Source trust cannot waive runner isolation.
- The preflight receipt is evidence, not a bearer capability or scheduling token.
- Later private execution must independently read and validate both exact source trust and current runner-isolation evidence before scheduling.

## Acceptance evidence target

- Unit tests prove fork PR, same-repo PR, wrong branch/repository, failed CI and malformed provenance cannot become private-runner eligible.
- Unit tests prove a canonical successful main push still requires isolation when no runner evidence is supplied.
- Unit tests prove unsafe isolation is blocked and safe isolation permits only already-trusted source.
- Receipt serialization is deterministic and secret-free.
- Workflow-shape tests prove the preflight uses GitHub-hosted execution, read-only permissions, no secrets, no `self-hosted`, no `pull_request_target`, and does not check out the triggering candidate SHA.
- Existing CI remains green on the exact PR head.
- Merge/post-merge CI must pass before integration verification is claimed.
- No live self-hosted runner, sandbox, private credential or LAN execution is claimed.
