## Required product behaviour

1. **One authority, many views.** Financial dashboards, review sheets, charts, allowance views, purchase archives and asset views are projections/input surfaces over canonical MIRROR entities/events/evidence. None becomes a second writable truth source.
2. **Economic-event dedupe.** A card/bank transaction is money movement; an order, receipt, shipment, cancellation, return or refund email is evidence about that event. Evidence must not create duplicate spending. A return request is not a refund until the economic credit is evidenced.
3. **Retirement contribution lever removed.** Financial Escape must not model reducing retirement contributions as a payoff accelerator. Remove contribution-rate controls, reduction scenarios, charts, recommendations and rate-dependent payoff/mileage projections. Factual retirement assets may remain part of asset/net-worth tracking and factual contribution evidence may remain as non-operational history.
4. **Confidence semantics are evidence-specific.** Do not label the whole finance model low-confidence merely because the forward trajectory has few daily snapshots. Distinguish source/data evidence quality from forecast-trajectory maturity and from unresolved item-level classifications.
5. **Allowance ownership and debit.** A canonical positive spend event explicitly assigned to an allowance owner debits that owner’s allocation immediately in the projection. Replay/duplicate evidence must not debit twice. A matched refund/credit reverses the economic effect. Provider-observed cash balances are not mutated by the allocation projection.
6. **Three-axis spending semantics remain independent.** Purpose/category, necessity, and allowance permission/owner are separate facts. Unknown stays unknown until supported by evidence or user correction.
7. **Granular source reconciliation.** Reconcile all currently available connected cash/card account activity, the supplied mail archive, current connected mail evidence, and the available marketplace purchase history. Every source record must end in a deterministic disposition such as canonical event/evidence match, non-economic support evidence, duplicate/replay, excluded transfer/payment, unresolved review, or unsupported/no-match.
8. **Cancellation/return/refund integrity.** Order cancellation, return and refund evidence must be linked to the same purchase/order/economic-event lineage. Refunds reduce net economic spend only when a matching credit/economic reversal is supported.
9. **Receipt/evidence preservation.** Preserve stable provenance and source identity; do not delete or rewrite source evidence merely to make projections neat.
10. **Asset acquisition linkage.** When purchase evidence supports that an acquired item is a durable physical asset/tool, link or create one canonical asset from the canonical purchase/receipt lineage rather than inventing a second inventory truth. Capture exact supported identifiers such as model/part/SKU/ASIN/serial where available; never guess them.
11. **Manual/warranty enrichment.** For sufficiently identified assets, preserve manufacturer/manual/warranty evidence or links with provenance. Missing exact identification remains an explicit evidence gap rather than a guessed model.
12. **Ongoing reconciliation direction.** The product must support repeatable evidence reconciliation of new mail/provider/account evidence into the same canonical model. This packet proves the current bounded audit and records any runtime/scheduler work that cannot truthfully be completed in the present provider lane as separate backlog work rather than pretending continuous execution already exists.

## Private-live checkpoint — one-authority spending integration

- The canonical economic-event ledger is the spending query authority. Stable event IDs remain the join/update key.
- The spending review sheet is a bounded user-input surface keyed by canonical event ID. It supplies semantic overrides; it is not an analytics authority.
- The spending insights/dashboard sheet is a derived projection over the canonical ledger. Exact private readback found zero formula references from the insights projection back to the review input surface.
