## Acceptance criteria

1. A caller must supply an explicit `StudioActivationPlan`; the execution boundary cannot create approval authority.
2. Activation requires a `CapabilityEvaluation` whose WRITE and REMOTE_READBACK decisions are both allowed.
3. An explicit source target binds provider ID, service ID and public logical target reference; it contains no credential/token/endpoint/private host fields.
4. Provider/service identity in the capability evaluation must match the source target.
5. The adapter preflight must report exact current revision/state before mutation.
6. Activation proceeds only when preflight current revision equals the plan base revision, unless exact readback already proves the same plan was applied and replay can return zero-write success.
7. The adapter receives exact approved proposed revision/source digest plus expected-current revision. Core code emits no provider-specific command or shell material.
8. Mutation success is not enough: exact post-write remote readback must confirm the adapter-returned applied revision and approved source digest/state contract before success is reported.
9. Readback mismatch produces recovery-required evidence rather than success or fabricated rollback.
10. Activation receipt preserves packet/work/change/approver/base/proposed/applied revision/source digest/target/evidence identity deterministically and secret-free.
11. Explicit rollback requires the successful activation receipt, the original activation plan, verified WRITE and REMOTE_READBACK capability, and exact currently applied revision.
12. Rollback requests only the plan's recorded prior revision/state anchor; stale current state blocks with zero mutation.
13. Rollback reports success only after exact remote readback matches the rollback adapter result and recorded prior state identity.
14. Adapter exceptions fail closed with deterministic reason codes and no fabricated success.
15. Replay of an already verified activation returns a deterministic no-op receipt and does not call mutation.
16. No automatic rollback occurs after activation/readback failure; recovery remains explicit and evidence-driven.
17. Direct tests cover capability denial, identity mismatch, stale preflight, success, replay/no-op, readback mismatch, adapter error, rollback success, stale rollback and rollback readback mismatch.
18. Public contracts expose no credentials, tokens, provider endpoints, host/IP/network identity, shell commands, runner labels or model paths.
19. Existing Studio tests remain green; repository CI passes on exact packet head; merge uses expected-head protection; post-merge exact-SHA CI passes before integration verification.
