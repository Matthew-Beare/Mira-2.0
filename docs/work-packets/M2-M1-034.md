## Objective

Implement the first bounded provider-neutral `FEATURE-SHARE-001` seam required by MIRA Studio: represent a privately owned feature change as a deterministic sanitized share package with exact source/change provenance, declared feature/dependency scope and compatibility constraints; validate that package without trusting its producer; and inspect an imported package as inert candidate material only.

This packet does **not** publish to GitHub or any registry, choose a sharing provider, install/import files into an active MIRA deployment, mutate source, activate behavior, invoke a model, or implement final Studio UX.

## Acceptance criteria

1. Export requires explicit private feature ownership identity plus exact reviewed change/source provenance.
2. Package carries authored feature IDs, dependency IDs, compatibility bounds and content digests deterministically.
3. Public package contract rejects credentials, tokens, provider endpoints, host/network identities, user-specific provider/resource identifiers and obvious private operational material.
4. Validation recomputes all package digests and rejects missing, duplicate, malformed or internally inconsistent material.
5. Import inspection is inert: it can return compatibility/dependency findings but has no activation/source-mutation authority.
6. Imported packages cannot claim approval, activation, provider capability or remote-readback evidence merely by containing similarly named fields.
7. Same package material yields the same package ID and canonical bytes.
8. Tests cover successful roundtrip plus privacy, tamper, duplicate, compatibility, dependency and authority-escalation failures.
9. No live provider publication/import/activation claim is made.
10. Repository CI must pass on the exact packet head before merge; post-merge exact-SHA CI is required for integration verification.
