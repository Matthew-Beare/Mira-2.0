## Objective

Implement the first bounded provider-neutral `FEATURE-SHARE-001` seam required by MIRA Studio: represent a privately owned feature change as a deterministic sanitized share package with exact source/change provenance, declared feature/dependency scope and compatibility constraints; validate that package without trusting its producer; and inspect an imported package as inert candidate material only.

This packet does **not** publish to GitHub or any registry, choose a sharing provider, install/import files into an active MIRA deployment, mutate source, activate behavior, invoke a model, or implement final Studio UX.

## Acceptance criteria and evidence

1. **Private ownership + reviewed provenance — PASS.** Export requires a private owner identity, exact change ID, source revision and reviewed-source SHA-256. Only a domain-separated SHA-256 ownership fingerprint is exported; the raw private owner identity is not package material.
2. **Deterministic declared scope — PASS.** Package carries sorted feature IDs, dependency IDs, runtime-schema compatibility bounds, artifact paths and content digests.
3. **Privacy failure — PASS.** Public artifact/path validation rejects obvious credential/secret markers, provider document URLs, OAuth/service identifiers, email addresses, private-network addresses, token-like values, path traversal and credential-named paths.
4. **Independent integrity validation — PASS.** Import validation recomputes artifact digests and the canonical package ID and rejects malformed schema, duplicate/unsorted IDs, feature/dependency overlap, duplicate/unsorted artifacts, bad base64 and tampering.
5. **Inert import inspection — PASS.** Import inspection reports runtime compatibility, missing dependencies and already-present features only. `activation_authorized`, `source_mutation_authorized` and `install_authorized` are always false.
6. **Authority escalation rejection — PASS.** Imported material containing approval, activation, install, provider-capability, remote-readback or similar authority fields fails closed rather than gaining authority from self-assertion.
7. **Deterministic identity — PASS.** Identical package material yields identical canonical bytes/package ID; changed artifact content changes package identity.
8. **Adversarial tests — PASS.** `tests/test_feature_share.py` contains 20 direct tests covering roundtrip, privacy, tamper, duplicate/order, compatibility, dependency and authority-escalation behavior.
9. **Evidence ceiling preserved — PASS.** No provider publication/import installation/source mutation/activation is implemented or claimed.
10. **Repository exact-head CI — PASS at implementation/ownership head.** CI #576 / run `34521587319` on `bd9e71ad4fa5c0b560e0c2b94a57716bbf95b262` passed compile, feature registry, product lifecycle ledger, Personal starter distribution, work-session alignment, code ownership, Android unit/proof build/provenance/retention, Python unit tests and Workspace Apps Script tests.
