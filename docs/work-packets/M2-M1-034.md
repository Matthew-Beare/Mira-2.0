## Objective

Implement the smallest complete provider-neutral integrity core needed for safe feature sharing and import staging.

A shared package must bind exact public artifact descriptors to exact sanitization evidence and source provenance, carry canonical dependency/contract requirements, evaluate compatibility against a target MIRA feature-registry snapshot, reconcile against existing private/imported/forked ownership state, and emit only an inert import staging plan. Imported material never becomes active merely because it was fetched, validated or staged.

## Planned contracts

1. **Share artifact descriptor** — safe relative path, content digest, byte length and media type; no raw private source or provider binding in manifest metadata.
2. **Sanitization evidence** — exact artifact path/digest, policy revision digest, outcome and evidence digest. Publication-ready manifest construction fails closed unless every artifact has exactly one passing matching record under the declared policy.
3. **Share manifest** — schema version, package ID/revision, exact source revision and source-tree digest, optional parent package lineage digest, required canonical feature IDs, required declared-contract IDs, artifact descriptors, sanitization-policy digest and evidence digests; deterministic canonical JSON and package digest.
4. **Target compatibility snapshot** — product ID, canonical feature-registry digest, available feature IDs, available contract IDs and supported share-schema versions. A helper may derive feature IDs directly from `mira.feature_registry.FeatureRegistry`.
5. **Installed feature record** — package identity/revision/digest plus local ownership state (`private_local`, `imported`, `forked`) and optional local-overlay digest, without embedding user identity in shared/public material.
6. **Import decision** — deterministic blockers plus optional inert staging plan for initial import or upgrade. Exact replay is no-op; same-revision/different-digest is conflict; downgrade is blocked; private-local identity collision is blocked; fork/local overlay requires explicit review rather than overwrite.

## Acceptance criteria

- Manifest serialization and package digest are deterministic regardless of input order.
- Unsafe/duplicate artifact paths, malformed digests, invalid sizes/media types, duplicate package requirements or malformed lineage are rejected.
- Sanitization is evidence-bound rather than hand-waved: missing, failed, duplicate, path-mismatched, digest-mismatched or policy-mismatched evidence prevents a publication-ready package.
- Sanitization evidence cannot silently authorize an artifact other than the exact bytes/digest it inspected.
- Shared manifest contains no raw artifact payloads, credentials, provider endpoints, host identities, private account identifiers or activation controls.
- Compatibility requires the supported share schema plus every declared canonical feature and contract dependency; missing requirements fail closed with deterministic blockers.
- Target feature IDs are derived from the existing canonical feature registry when a registry helper is used; this packet creates no second feature catalog authority.
- Import reconciliation protects local ownership: a package cannot overwrite a private-local feature identity, a locally modified/forked import requires review, same-revision divergent digest is conflict, and downgrade is blocked.
- Exact same package revision/digest is deterministic no-op.
- Initial compatible import and clean upgrade produce an inert staging plan only; there is no activation flag, execution method or provider mutation in this module.
- Staged import plan preserves package, registry and dependency evidence needed by later Studio preview/test/approval flow.
- Direct tests cover malformed input, sanitization failures, deterministic serialization, compatibility failures, ownership conflict, local modification, replay, upgrade, downgrade and no-activation public contract shape.
- New production code is registered under a bounded component with direct test import.
- Exact-head repository CI must pass before merge; expected-head merge and post-merge exact-SHA CI are required before integration verification.
