## Product-owner directive captured

The 2026-09-08 compute-fabric / Studio directive is accepted as durable product direction. The whole directive is larger than one safe work packet and is therefore decomposed below rather than silently stuffed into one branch.

The accepted direction includes:

1. MIRA Studio remains the prompt-driven bounded feature generator; local compute is shared optional infrastructure, never a hard feature dependency.
2. Standard onboarding must remain usable without local infrastructure. Advanced onboarding extends the existing MIRROR-integrated interview with optional compute/server/storage/development capability registration.
3. Local workers are generic capability-advertising agents. Public source must not hard-code private hostnames, addresses, credentials, hardware identities, provider resource IDs, or private operational state.
4. Routing considers capability, privacy/policy, cost, priority, availability, health and explicit compute mode. Required modes are `off`, `normal`, and `aggressive`. Worker presence never overrides user policy.
5. Private deployment may use an always-on control-plane host plus optional burst GPU workers. Those private machine details remain deployment configuration, not public feature logic.
6. No raw inference, Python or shell service is exposed publicly. Preferred connectivity is scoped LAN/VPN or authenticated outbound worker registration behind a narrow semantic API.
7. Durable jobs must support preemption/resume metadata. Wake, heartbeat, drain, safe shutdown, do-not-wake, do-not-shutdown, interactive/gaming and maintenance/fault locks are required directions.
8. Local models are capability profiles, not product dependencies. Model/profile selection is benchmark- and evidence-driven.
9. Competitive/high-assurance Studio development may dispatch independent implementations to separate Git branches, run deterministic CI, cross-critique outputs and integrate only through reviewed work while preserving provenance.
10. AI-generated MIRROR facts normally enter as proposed/staged evidence with model/version/confidence/provenance/reconciliation state unless deterministic policy authorizes acceptance.
11. Trusted self-hosted CI must validate origin and isolate untrusted code; arbitrary public fork/PR code must not run unrestricted on trusted private machines.
12. Deterministic computation is preferred for numerical/algorithmic work. Scenario inputs must be classified as MIRROR fact, current external fact, data-derived estimate, or explicit assumption with source/as-of/confidence/uncertainty.
13. Prometheus/Grafana-compatible observability is required for worker/task health, compute/cooling telemetry, CI/tests, failures and local-versus-hosted usage.
14. Hardware safety is deterministic. Critical configured sensor or cooling faults stop affected workloads and may trigger safe shutdown. Thresholds are configuration/evidence, never invented by an LLM.
15. Hosted escalation is allowed when local quality is insufficient, work is urgent, provider interaction requires hosted execution, or higher-authority review adds value. Consumer UI automation must not be used to evade limits.
16. Human-only blockers become durable `requires-human-action` state with the minimum manual action, immediate walkthrough, verification and resume from checkpoint.
17. Optional external orchestration systems may sit behind MIRA policy but do not become MIRA's architectural center.
18. Google Sheets remains a reusable projection/control/reconciliation surface over MIRROR, not a competing authority.
19. ## Why this packet is bounded

The directive spans runtime routing, worker agents, durable scheduling, networking, power control, hardware safety, CI trust, deterministic analytics, Studio orchestration, onboarding, telemetry, GitHub escalation and several domain verticals. Implementing all of that in one packet would violate MIRA's packet policy and create an unreviewable mega-branch.

This packet therefore implements only the provider-neutral **execution routing contract** that downstream local/hosted workers can plug into.

## Objective

Extend the existing `PROVIDER-001` runtime router so MIRA can make a deterministic, policy-first execution-lane decision without hard-coding any private machine, model, provider or network topology.

The foundation must distinguish local versus hosted lanes, expose explicit local compute mode, require runtime capability matches, fail closed on unavailable/unhealthy/locked workers, preserve privacy/data-classification policy, and rank eligible lanes deterministically.

## Acceptance criteria for M2-M1-021

1. Existing provider/runtime routing behavior remains backward compatible.
2. Runtime candidates can declare generic local/hosted execution kind without private machine names.
3. Local compute mode supports exactly `off`, `normal`, and `aggressive` semantics:
   - `off`: all local candidates are policy-blocked;
   - `normal`: eligible local and hosted candidates compete by deterministic priority/cost ordering;
   - `aggressive`: eligible local candidates rank ahead of hosted candidates, without overriding health, lock, capability, authorization or data policy.
4. A request can require generic runtime capabilities; candidates missing any required capability fail closed.
5. Offline, draining, faulted or unknown-health local workers cannot be selected.
6. An interactive/do-not-use lock prevents selection regardless of compute mode.
7. Existing data-classification and explicit approval policy continues to apply before runtime selection.
8. Candidate ordering does not affect the selected result.
9. No credential, host address, model secret or private deployment identifier is added to public source/tests/docs.
10. `tests/test_compute_routing.py` covers off/normal/aggressive routing, capability mismatch, health/availability, interactive lock, policy precedence and deterministic ranking while the existing router suite continues to cover provider-routing compatibility.
11. Architecture documentation defines the seam between this router and later worker-registry/scheduler/agent packets, including what is intentionally not yet implemented.
12. Exact-head CI must pass before merge. No live worker/device/provider claim is made by this packet.
