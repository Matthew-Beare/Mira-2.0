# M2-M1-020 — Google Sheets operational control-surface foundation

## Objective

Create the smallest reusable MIRA/MIRROR Google Sheets projection and reconciliation foundation needed by multiple modular operational features, while durably registering the customer-approved feature family and preserving existing domain authorities.

## Related feature/work IDs

Primary work: `SHEETS-CONTROL-001`.

Primary features: `SHEETS-001`, `STUDIO-001`.

Related preserved features/invariants: `MIRROR-001`, `AUTH-001`, `STORE-001`, `RECOVERY-002`, `DATA-001`, `DIST-001`, `DIST-002`, `DEV-004`, `DEV-005`, `OBS-001`, `CAREER-001`, finance/asset/inventory features already present in `FEATURES.md`.

## Scope

1. Register the uploaded modular-life-operations / Sheets feature family in canonical Git without duplicating existing semantics.
2. Define a reusable Sheets control-surface contract supporting canonical read-only projections, controlled editable projections, derived analytical views, temporary non-authoritative prototypes, reconciliation queues and generated dashboards.
3. Define explicit column/range ownership, validation, write-back, optimistic conflict detection, provenance, timestamps, retries/failure truth and audit/readback semantics.
4. Reuse the existing Google Sheets gateway, structured-state, Workspace and Studio/distribution foundations rather than creating a second store or plugin framework.
5. Inspect current Google Sheets/API/Apps Script limits and record material product constraints and high-value Sheets ideas.
6. Add deterministic synthetic tests for projection definitions, editable-field policy, conflict behavior and sanitization boundaries.
7. Register downstream bounded work for reusable Job Search + market boards, People Discovery integration, Finance Operations telemetry, Vehicle Operations, Inventory Operations, MIRA Operations dashboard, Sheets prototype-to-MIRROR workflow, automation and Studio packaging.
8. Register an optional local coding-worker backlog lane using the existing provider/local-service/development governance boundaries; first evaluated target is NVIDIA Llama-3.3-Nemotron-Super-49B-v1.5 or a suitable lower-precision variant through a replaceable OpenAI-compatible local runtime.

## Explicit non-goals

- Do not implement every downstream domain in this packet.
- Do not make Google Sheets canonical authority.
- Do not duplicate durable identity, provenance, classification, dedupe or domain business logic in formulas.
- Do not touch protected legacy production Sheets or private user data.
- Do not implement education/course/certification/study-progress/skills-gap tracking as a separate operational feature in this packet.
- Do not add automated professional outreach.
- Do not make a local LLM capable of independently merging/pushing or mutating live providers.

## Acceptance criteria

1. Canonical feature/backlog state captures all accepted downstream feature work and local coding-worker direction with stable IDs or explicit mappings to existing stable features.
2. Shared Sheets control-surface feature has a narrow reusable contract and no second-source-of-truth semantics.
3. At least two synthetic downstream feature definitions can use the same projection/reconciliation contract without domain-specific logic leaking into the shared layer.
4. Controlled edits are allowlisted, validated, revision-aware and fail closed on conflicting canonical changes.
5. Every projection definition declares one of: canonical read-only projection; controlled editable projection; derived analytical view; temporary non-authoritative prototype; reconciliation queue; generated dashboard.
6. Public/sanitized definitions contain no private IDs, values, credentials, people, accounts, VINs, locations, spreadsheet IDs or Drive IDs.
7. Existing Google Sheets/Workspace infrastructure is reused.
8. Material Google Sheets/API/Apps Script limitations and workarounds are documented.
9. Additional high-value Sheets ideas discovered during implementation are recorded visibly.
10. Direct tests and repository gates pass on exact head before merge.
