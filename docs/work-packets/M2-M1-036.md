## Acceptance criteria

1. One Studio session is bound to exact packet/work/change identity, change kind, human-readable objective and declared feature/dependency context.
2. Supplied staged-change evidence is evaluated through existing `studio_competition` contracts rather than reimplementing readiness logic.
3. The surface deterministically emits a lifecycle phase, blockers, readiness flags and one explicit next action.
4. No activation-ready state exists without an exact approval-bound `StudioActivationPlan`.
5. Activation/rollback receipts map truthfully to applied, blocked, recovery-required and rollback-ready/rolled-back states.
6. Sharing is an optional separate action and cannot be inferred from activation.
7. Imported shared material is always review-required and carries no source-mutation/install/activation authority.
8. Public Studio-surface contracts contain no credential/token/secret/provider-endpoint/host/IP/MAC/shell/command/runner-label/model-path fields.
9. Replaying identical evidence returns identical surface state.
10. Direct adversarial tests cover missing/failed preview/test evidence, explicit approval, stale/mismatched identity, activation recovery, rollback, sharing separation and inert import review.
11. Code ownership and repository-wide CI pass at the exact implementation head.
