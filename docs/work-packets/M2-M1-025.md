## Objective

Implement the provider-neutral authentication boundary for optional compute workers. A provisioned worker credential must be restricted to one stable worker/principal identity, stored only as a verifier, expire/revoke deterministically, require explicit secure-channel evidence, and reduce successful authentication to the existing secret-free `WorkerRegistryIdentityEvidence` consumed by worker registration/routing.

This is a contract/synthetic implementation packet. It does not deploy a listener, issue real certificates, configure VPN peers, bind private hosts, expose execution endpoints, execute jobs, load models, wake/shut down machines, or claim live network/worker proof.

## Reuse decision

- `mira/http_transport.py` already owns provider-neutral credential/session authentication, verifier-only bearer storage, TTL/revocation and protected transport semantics.
- `mira/service_state.py` already owns `WorkerRegistryIdentityEvidence` and durable secret-free worker registry semantics.
- `mira/runtime_router.py` already consumes secret-free worker identity proof and rejects unverified/revoked/principal-mismatched workers.

M2-M1-025 therefore extends the existing API transport/auth component rather than adding another authentication service or trusting LAN presence.

## Planned implementation

1. Add generic approved secure-channel kinds, initially mutual TLS, WireGuard and authenticated outbound registration.
2. Add secret-free channel evidence with authenticated/confidential flags and observed-at freshness.
3. Add one-time worker credential issuance with cryptographically strong opaque token generation and verifier-only in-memory storage for the synthetic boundary.
4. Bind each session to exactly one worker ID and principal ID plus an explicit allowed-channel set.
5. Authenticate only when token, worker binding, active TTL/revocation state and approved fresh secure-channel evidence all match.
6. Return `WorkerRegistryIdentityEvidence(state="verified")`; do not return generic API grants or make workers ordinary same-user API clients.
7. Add adversarial tests for wrong worker/token, expired/revoked sessions, unapproved/insecure/stale/future channels, verifier-only storage and absence of raw execution/private binding surfaces.
8. Prove existing WSGI API does not gain worker execution, inference, Python or shell routes.

## Security/integrity rules

- No blanket LAN trust.
- Worker network location is not identity.
- Raw credentials are returned only at provisioning and never stored in session metadata or durable worker state.
- Public code contains no real hostname, IP address, MAC, certificate, VPN peer, private key, model path or machine identifier.
- Secure-channel evidence is necessary but not sufficient; credential and worker/principal binding remain mandatory.
- Worker credentials do not carry generic MIRROR API grants.
- Revocation and expiry fail closed.
- Freshness is deterministic; future channel evidence is invalid.
- No raw shell, Python or inference endpoint is introduced.
