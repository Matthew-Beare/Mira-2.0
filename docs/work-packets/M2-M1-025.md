## Objective

Implement the provider-neutral authentication boundary for optional compute workers. A provisioned worker credential is restricted to one stable worker/principal identity, stored only as a verifier, expires/revokes deterministically, requires explicit secure-channel evidence, and reduces successful authentication to the existing secret-free `WorkerRegistryIdentityEvidence` consumed by worker registration/routing.

This is a contract/synthetic implementation packet. It does not deploy a listener, issue real certificates, configure VPN peers, bind private hosts, expose execution endpoints, execute jobs, load models, wake/shut down machines, or claim live network/worker proof.

## Reuse decision

- `mira/http_transport.py` already owns provider-neutral credential/session authentication, verifier-only bearer storage, TTL/revocation and protected transport semantics.
- `mira/service_state.py` already owns `WorkerRegistryIdentityEvidence` and durable secret-free worker registry semantics.
- `mira/runtime_router.py` already consumes secret-free worker identity proof and rejects unverified/revoked/principal-mismatched workers.

M2-M1-025 extends the existing API transport/auth component rather than adding another authentication service or trusting LAN presence.

## Implemented boundary

1. Approved secure-channel classes are limited to `mutual_tls`, `wireguard`, and `authenticated_outbound`.
2. `WorkerChannelEvidence` carries only channel class, peer-authentication truth, confidentiality truth and observed epoch time.
3. `InMemoryWorkerSessionStore` provisions one-time opaque worker credentials and stores only SHA-256 verifiers.
4. Each worker session binds exactly one `worker_id`, one `principal_id`, one explicit allowed-channel set, issuance time and expiry time.
5. Authentication rejects wrong worker/token, expired or revoked sessions, unapproved channels, unauthenticated/unconfidential channels, stale channel evidence and future-dated channel evidence.
6. Successful authentication returns the existing `WorkerRegistryIdentityEvidence(state="verified")`; no `AuthenticatedPrincipal`, actor/client identity or generic MIRROR grants are minted.
7. The existing WSGI route set is unchanged. Explicit synthetic tests verify that worker-execute, inference, Python and shell routes remain absent.
8. No private hostname, IP address, MAC, certificate/private-key material, VPN peer, model path or raw task/command payload is part of worker session metadata.

## Trusted channel-observation invariant

`WorkerChannelEvidence` is an internal trusted transport observation. A later live listener/adapter must construct it from the actual authenticated connection context, such as verified mutual TLS, an authenticated WireGuard context, or an authenticated outbound registration channel. It must never accept the evidence booleans/channel class as worker-supplied request claims. M2-M1-025 intentionally does not implement that live listener, so this invariant remains a required integration constraint for the later deployment/transport packet.

Secure-channel evidence is necessary but not sufficient: credential possession, exact worker binding, active session state and channel policy must all succeed.

## Security/integrity rules

- No blanket LAN trust.
- Worker network location is not identity.
- Raw credentials are returned only at provisioning and never stored in session metadata or durable worker state.
- Public code contains no real hostname, IP address, MAC, certificate, VPN peer, private key, model path or machine identifier.
- Worker credentials do not carry generic MIRROR API grants.
- Revocation and expiry fail closed.
- Freshness is deterministic; future channel evidence is invalid.
- No raw shell, Python or inference endpoint is introduced.
