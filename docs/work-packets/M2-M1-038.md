## Objective

Implement the first stock-ChatGPT/no-app MIRA Studio intake boundary so a customer can describe a desired preference, workflow, or capability in ordinary language without supplying packet IDs, work IDs, change IDs, Git branches, providers, model names, or implementation details.

The deterministic boundary accepts the raw user request plus a host/model-produced semantic interpretation, validates that interpretation against the exact canonical feature registry, derives declared feature dependencies, generates stable private intake identity, preserves explicit customer constraints separately from assistant assumptions, surfaces materially unresolved blockers/questions, and emits one bounded reviewable draft plus one customer-facing next action.

The host/model may interpret natural language; this packet does not claim deterministic code can semantically understand arbitrary prose without such interpretation. The deterministic layer is the authority for validation, registry grounding, identity, constraint/assumption separation, dependency derivation, and whether a draft is ready for customer review.

This packet does not invoke a model, create Git branches from intake, assign an implementation packet from intake, mutate source/provider state, publish/share a feature, install an import, infer approval, activate behavior, or implement final graphical Studio UX.

## Implemented deterministic boundary

- `StudioIntakeRequest` contains only ordinary-language request text plus explicit customer constraints.
- `StudioSemanticInterpretation` carries host/model-produced semantic evidence for deterministic validation.
- Interpretation distinguishes preference/workflow/feature using `StudioChangeKind` and carries a concise desired outcome.
- Proposed feature scope is validated against the exact `FeatureRegistry`; unknown feature IDs fail closed.
- Dependency scope is derived deterministically and transitively from selected feature records rather than trusted from model prose.
- Explicit customer constraints remain distinct from assistant/model assumptions; exact constraint echo is required.
- Reported constraint conflicts and attempts to smuggle implementation/approval/execution authority fail closed.
- Material unresolved questions produce deterministic blockers and one clarification next action; otherwise the result becomes review-ready.
- `draft_id` is deterministic and binds normalized intake evidence plus exact registry SHA.
- Draft authority booleans are structurally fixed false for implementation, source mutation, publication, install, inferred approval and activation.
